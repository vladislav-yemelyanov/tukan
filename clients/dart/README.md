# Tukan Dart Client (`tukan`)

Zero-dependency, `dart:io`-native typed HTTP client built for Dart models, enums, and `Paths` operation trees generated by Tukan (`api.dart`).

## 1. Overview & Design Principles

Conforms to the shared Tukan HTTP client requirements matrix (`docs/client-requirements.md` in the Tukan repository).

- **Zero external dependencies:** Uses only the Dart standard library (`dart:async`, `dart:convert`, `dart:math`, `dart:typed_data`, plus `dart:io` for the default `IoHttpTransport`). Targets Dart SDK `>=3.5.0 <4.0.0`.
- **Zero-import boundary in `api.dart`:** Tukan-generated Dart files never import `tukan`. Instead, generated ready operations expose a Dart 3 structural record `OperationRequest<T, E>` that structurally matches `TukanOperation<T, E>`.
- **Compile-time route & slot safety:** Generated `Paths` classes enforce valid route segments, HTTP methods, inline path parameters, required slots (`query`, `headers`, `cookie`, `body`, `pathParams`), success payload type `T`, and contract error type `E` before code compiles.
- **Strict non-throwing contract:** Every client operation resolves to `Future<ApiResult<T, E>>` (`ApiSuccess<T, E>` or `ApiFailure<T, E>`). Even `TimeoutException`, cancellation, contract-drift `TypeError`s during `fromJson`, and exceptions in hooks are captured into a 7-subtype `sealed class ApiError<E>` and routed through `onError` hooks.

## 2. Setup & Configuration

### Add `tukan` to `pubspec.yaml`

Install `tukan` from pub.dev:

```yaml
dependencies:
  tukan: ^0.1.0
```

For local monorepo development against this repository, you can also use `path: ../../clients/dart`.

Generate your Dart API file(s) from `tukan.json5`:

```json5
{
  outputs: [
    { language: "dart", path: "./lib/generated" },
  ],
  specs: [
    { name: "tasks", input: "./specs/tasks.json" },
  ],
}
```

### `TukanClient` & `TukanClientConfig`

```dart
import 'package:tukan/tukan.dart';

final client = TukanClient(
  TukanClientConfig(
    baseUrl: 'https://api.example.com',
    timeout: const Duration(seconds: 10),
    headers: const <String, String>{'Accept': 'application/json'},
    headersProvider: (HeadersContext ctx) async => <String, String>{
      'Authorization': 'Bearer ${await tokenStore.getAccessToken()}',
    },
  ),
);
```

| Field | Type | Default | Behavior |
|---|---|---|---|
| `baseUrl` | `String` | *(required)* | Trailing slashes are trimmed. Can be empty (`''`) or a path prefix (`'/proxy/'`) when paired with a custom transport. |
| `headers` | `Object?` | `null` | Static base headers (`HttpHeadersMap`, `Map<String, Object?>`, or any Tukan model with `toJson()`). |
| `headersProvider` | `HeadersProvider?` | `null` | Async/sync per-request base header callback receiving `HeadersContext(method, path, uri)`. |
| `transport` | `HttpTransport?` | `null` | Custom transport. Defaults to `IoHttpTransport` on VM/mobile/desktop; required on web (`dart:io` unavailable). |
| `timeout` | `Duration?` | `null` | Client-wide request timeout, overridable per call via `timeout:`. Zero or negative duration times out immediately. |
| `followRedirects` | `bool` | `true` | Redirect following setting forwarded to `IoHttpTransport` (unless overridden per call). |
| `maxRedirects` | `int` | `5` | Maximum redirects for `IoHttpTransport`. |
| `persistentConnection` | `bool` | `true` | HTTP keep-alive setting for `IoHttpTransport`. |
| `errorFromJson` | `Map<int, JsonFactory<Object?>>?` | `null` | Client-wide status-code JSON factories (`Map<String, dynamic> -> Object?`). |
| `errorDecoders` | `Map<int, ResponseDecoder<Object?>>?` | `null` | Client-wide status-code decoders (`Object? -> Object?`). |
| `defaultErrorDecoder` | `ResponseDecoder<Object?>?` | `null` | Client-wide fallback error decoder when no status-specific decoder matches. |
| `onRequest` | `List<OnRequestHook>` | `const []` | Hooks invoked in order after serialization; may mutate `RequestContext` (`uri`, `headers`, `body`, `extra`, redirect flags). |
| `onResponse` | `List<OnResponseHook>` | `const []` | Hooks invoked in order after transport response; returning a non-null `RawHttpResponse` replaces the active response. |
| `onError` | `List<OnErrorHook>` | `const []` | Hooks invoked in order for every `ApiFailure` before it is returned. Signature: `FutureOr<void> Function(RequestContext, ApiError<Object?>)`. |

Call `client.close()` when disposing a client that owns its default `IoHttpTransport`. When you pass an external `HttpTransport` via `config.transport`, `client.close()` leaves that transport open so you manage its lifecycle directly.

## 3. Type-Safe `Paths` Tree & `client.send(...)`

Tukan generates a nested `Paths` class hierarchy inside `api.dart` matching the exact OpenAPI path structure. Store the resource root in a service class with `static final`:

```dart
import 'package:tukan/tukan.dart';
import '../generated/tasks.dart' as tasks;

final class TasksService {
  static final _tasks = tasks.Paths.api.v1.tasks;
  final TukanClient client;

  const TasksService({required this.client});

  Future<ApiResult<tasks.TaskListResponse, tasks.ApiErrorResponse>> list({
    tasks.TaskStatus? status,
    int? page,
  }) =>
      client.send(
        _tasks.get.query(status: status, page: page).request,
      );

  Future<ApiResult<tasks.Task, tasks.ApiErrorResponse>> getById(String taskId) =>
      client.send(_tasks.byTaskId(taskId).get.request);

  Future<ApiResult<tasks.Task, tasks.UpdateTaskError>> update(
    String taskId, {
    String? title,
    tasks.TaskStatus? status,
  }) =>
      client.send(
        _tasks.byTaskId(taskId)
            .patch
            .body(title: title, status: status)
            .request,
      );
}
```

### Bound Path Parameters vs. Fallback

- **Inline segment binding (`by<Param>(value)`):** Whenever every descendant operation under a `{param}` path segment declares `param` as a required path parameter with identical type and payload, Tukan generates a callable segment (`_tasks.byTaskId(taskId)`).
- **Conflict fallback:** If sibling operations under the same `{param}` segment declare incompatible types for `param` (for example `int` on `GET` vs `String` on `DELETE`) or omit the parameter, the path segment stays a getter and the operation builder exposes `.pathParams(...)` / `.withPathParams(...)` instead.

### Immutable Typestate Builders & `.request`

Every generated operation uses immutable typestate classes so incomplete requests do not compile:

- **0 required slots:** Entry class immediately exposes `OperationRequest<T, E> get request`.
- **1 required slot:** Entry class transitions to `<Op>Ready` when the required slot is set; optional slots can be chained before or after in any order.
- **2 required slots:** 4 states allow providing the 2 required slots in either order before exposing `.request`.
- **3+ required slots:** Linear staged chain (`base -> S1 -> ... -> Ready`).

Supported builder methods:

| Method | Purpose | Notes |
|---|---|---|
| `.query(...)` / `.withQuery(dto)` | Query parameters | Inline named args construct `*QueryParameters`; `.withQuery` accepts an existing DTO (or `null` when optional). |
| `.headers(...)` / `.withHeaders(dto)` | Header parameters | Same DTO/inline ergonomics. Merged with base headers. |
| `.cookie(...)` / `.withCookie(dto)` | Cookie parameters | Same DTO/inline ergonomics. |
| `.pathParams(...)` / `.withPathParams(dto)` | Unbound path params | Only present if not all `{param}` segments were bound inline. |
| `.body(...)` / `.withBody(value)` | Request body | Named parameters for named object schemas; positional `.body(value)` for primitives, lists, maps, or multi-media `Object?`. |
| `.contentType(String value)` | Request media type | Emitted when an operation declares 2+ request media types (defaults to `application/json` if present, otherwise first sorted media type). |
| `.request` | Terminal getter | Exposed **only** on the Ready state; yields `OperationRequest<T, E>`. |

Every path node and operation state also exposes `String get path` (exact OpenAPI template, e.g. `"/api/v1/tasks/{taskId}"`), and operation states expose `String get method` (uppercase HTTP method).

### Structural Contract (`OperationRequest<T, E>` ↔ `TukanOperation<T, E>`)

Generated `.request` returns an `OperationRequest<T, E>` record matching `TukanOperation<T, E>`:

```dart
typedef TukanOperation<T, E> = ({
  String method,
  String path,
  Map<String, dynamic>? pathParams,
  Map<String, dynamic>? query,
  Map<String, dynamic>? headers,
  Map<String, dynamic>? cookie,
  Object? body,
  String? contentType,
  T Function(Object? data) decodeResponse,
  Map<int, E Function(Object? data)?> errorDecoders,
  E Function(Object? data)? defaultErrorDecoder,
});
```

`client.send` also accepts per-call overrides alongside `operation`:

```dart
final result = await client.send(
  op.request,
  headers: const <String, String>{'X-Trace': 'override'},
  cookie: const <String, String>{'locale': 'en'},
  timeout: const Duration(seconds: 3),
  cancelToken: cancelToken,
  followRedirects: false,
  maxRedirects: 2,
  persistentConnection: false,
  extra: const <String, Object?>{'attempt': 1},
);
```

## 4. Result Model & Categorized Error Matrix

### `ApiResult<T, E>`

`ApiResult<T, E>` is a `sealed class` covariant in both `T` (decoded success type) and `E` (decoded contract error type):

- `ApiSuccess<T, E>` — `final T data`, `final RawHttpResponse response`, `ApiError<E>? get error => null`
- `ApiFailure<T, E>` — `final ApiError<E> error`, `final RawHttpResponse? response`, `T? get data => null`
- Shared helpers on `ApiResult<T, E>`: `isOk`, `isError`, `data`, `error`, `response`.

### Base `ApiError<E>` Members

All failures implement `sealed class ApiError<E> implements Exception`:

- `String get message` — human-readable summary (e.g. `'HTTP 400 Bad Request'`, `'Network request failed: ...'`)
- `RawHttpResponse? get response` — raw HTTP response when received
- `int? get status` — `response?.statusCode`
- `E? get body` — decoded contract error payload (`non-null` on `ApiResponseError<E>` when `E` is non-nullable; `null` on all other categories)
- `Object? get rawBody` — pre-decoded JSON/text payload or mismatched decoder result when available
- `Object? get cause` — underlying `Exception` or `Error` (`SocketException`, `FormatException`, `TypeError`, etc.)
- `StackTrace? get stackTrace` — captured stack trace when available
- `bool isStatus(int code)` — `status == code`
- `U? bodyAs<U>([int? code])` — checks typed `body` first, then falls back to `rawBody` (useful for manual `client.get<T>` calls or global `config.errorFromJson` outside `E`)
- `bool get isNetworkError` / `isTimeout` / `isCancelled` — convenience predicates matching `NetworkError<E>`, `TimeoutError<E>`, `CancelledError<E>`

### The 7 Error Categories

| Subclass | Trigger | Guaranteed Non-Null Fields | `body` (`E?`) | Safe to Retry? | Recommended App Handling |
|---|---|---|---|---|---|
| `ApiResponseError<E>` | HTTP non-2xx matched a contract/configured decoder and produced an `E`. | `status`, `response`, `body` (`E`), `message` | `E` (decoded) | No *(except 401 refresh)* | Show API `message`, render `fieldErrors`, redirect to login. |
| `UnexpectedHttpError<E>` | HTTP non-2xx outside the contract: undeclared status (e.g. `502`/`503`/`429`), empty body, malformed JSON on non-2xx, or error decoder threw. *(Also used when `E = Never` or a global decoder returned a non-`E` type.)* | `status`, `response`, `message` *(optional `rawBody`, `cause`, `stackTrace`)* | `null` | Only idempotent reads on `5xx`/`429` | Generic server error banner; report decoder failures (`cause != null`) to telemetry. |
| `NetworkError<E>` | Transport `Exception` before an HTTP response arrived (offline, DNS failure, connection reset, TLS handshake). | `cause`, `stackTrace`, `message` | `null` | Yes (with backoff) | Show "No connection" + Retry button. |
| `TimeoutError<E>` | Request exceeded `timeout` or `config.timeout` (`TimeoutException`). | `cause`, `stackTrace`, `message` *(optional `Duration? timeout`)* | `null` | For reads / idempotent ops | Show "Request timed out" + Retry. |
| `CancelledError<E>` | Aborted via `CancelToken.cancel([reason])` (`ApiCancelledException`). | `cause`, `stackTrace`, `message` *(optional `Object? reason`)* | `null` | No | Ignore silently in UI (navigation away, superseded search). |
| `DecodeError<E>` | Server returned `2xx`, but JSON parsing (`FormatException`) or `fromJson` decoding (`FormatException`, `TypeError`) failed — i.e., **backend contract drift**. | `status`, `response`, `cause`, `stackTrace`, `message` *(optional `rawBody`)* | `null` | **Dangerous for writes!** *(Server may have committed the mutation.)* | Generic failure message + log `cause`, `rawBody`, and `stackTrace` to telemetry. |
| `UnexpectedClientError<E>` | Failure during request construction (`stage: requestBuild`), hooks (`stage: hook`: `headersProvider`, `onRequest`, `onResponse`, `onError`), or transport/client Dart `Error` (`stage: internal`). | `stage` (`ClientErrorStage`), `cause`, `stackTrace`, `message` *(optional `response`)* | `null` | No *(fix caller/hook bug)* | Log `stage`, `cause`, and `stackTrace` to telemetry; show generic fallback in UI. |

### How Tukan Types `E` in `api.dart`

Depending on how many distinct decodable error schemas an OpenAPI operation declares across `4xx`, `5xx`, and `default`:

1. **0 decodable error models** (no `4xx`/`5xx`/`default` with a single-schema payload):
   `E = Never`. `ApiResponseError<Never>` can never be produced; any non-2xx response goes to `UnexpectedHttpError<Never>` with `rawBody` preserved.
2. **1 distinct decodable error model** (across one or more statuses, e.g. `401` and `404` both returning `ApiErrorResponse`):
   `E = ApiErrorResponse` directly.
3. **2+ distinct decodable error models** (e.g. `400` -> `ValidationErrorResponse`, `401`/`404` -> `ApiErrorResponse`):
   Tukan generates a `sealed class <OpBase>Error` (e.g. `CreateTaskError`, `UpdateTaskError`, `PostLoginError`) containing:
   - one nullable getter per distinct model (e.g. `ValidationErrorResponse? get validationErrorResponse => null`, `ApiErrorResponse? get apiErrorResponse => null`)
   - one `final class <Union><Model> extends <Union>` per model with `final <Model> value`, `const` constructor, `@override` getter, `==`, and `hashCode`.

### Narrowing Patterns in Application Code

**1. Concise UI message handling (no error model imports required):**

```dart
final result = await appServices.tasks.getById(taskId);
switch (result) {
  case ApiSuccess(:final data):
    setState(() => _selectedTask = data);
  case ApiFailure(:final error):
    setState(() {
      _notice = error.body?.message ?? error.message;
      _isError = true;
    });
}
```

**2. Multi-error endpoint narrowing via generated union getters (still zero error imports):**

```dart
final result = await appServices.tasks.create(title: title);
switch (result) {
  case ApiSuccess(:final data):
    _onCreated(data);
  case ApiFailure(:final error):
    if (error.body?.validationErrorResponse case final validation?) {
      setState(() {
        _fieldErrors = validation.fieldErrors;
        _notice = validation.message;
      });
      return;
    }
    setState(() => _notice = error.body?.apiErrorResponse?.message ?? error.message);
}
```

**3. Full categorized & exhaustive `switch`:**

```dart
switch (result) {
  case ApiSuccess(:final data):
    return data;
  case ApiFailure(error: CancelledError()):
    return null; // Ignore user/lifecycle cancellation
  case ApiFailure(error: NetworkError() || TimeoutError()):
    showRetryBanner('Connection issue. Please try again.');
  case ApiFailure(error: ApiResponseError(:final status, :final body)):
    // `body` is non-null `CreateTaskError` here!
    switch (body) {
      case CreateTaskErrorValidationErrorResponse(:final value):
        showFieldErrors(value.fieldErrors);
      case CreateTaskErrorApiErrorResponse(:final value):
        showErrorBanner('[$status] ${value.message}');
    }
  case ApiFailure(error: DecodeError(:final status, :final cause, :final stackTrace)):
    telemetry.captureException(cause, stackTrace, extra: {'status': status});
    showErrorBanner('Unexpected server response format.');
  case ApiFailure(error: UnexpectedHttpError(:final status, :final rawBody)):
    showErrorBanner('Server error $status: $rawBody');
  case ApiFailure(error: UnexpectedClientError(:final stage, :final cause, :final stackTrace)):
    telemetry.captureException(cause, stackTrace, extra: {'stage': stage.name});
    showErrorBanner('Client request failed.');
}
```

### Error Decoder Resolution Order

For a non-2xx response with a non-null parsed body, `TukanClient` resolves at most one decoder in the following priority order:

1. `operation.errorDecoders[status]` (or per-request `errorDecoders[status]`)
2. Per-request `errorFromJson[status]`
3. `config.errorDecoders[status]`
4. `config.errorFromJson[status]`
5. `operation.defaultErrorDecoder` (or per-request `defaultErrorDecoder`)
6. `config.defaultErrorDecoder`

- If a decoder runs and returns `decoded` where `decoded is E`, the failure is `ApiResponseError<E>(..., body: decoded, rawBody: rawParsed)`.
- If a decoder returns a value that is **not** an `E` (for example a global `config.errorFromJson` on an `E = Never` operation), or no decoder matched, or body was `null`, the failure is `UnexpectedHttpError<E>` (preserving `decoded`/`rawParsed` in `rawBody`).
- If the matched error decoder throws (e.g. `FormatException` or `TypeError`), the failure is `UnexpectedHttpError<E>` with `cause`, `stackTrace`, and `rawBody`.

## 5. Request Serialization, Headers & Response Parsing

### URI & Query Serialization (`serialization.dart`)

- Every `{key}` placeholder in `path` is substituted from `pathParams` using `Uri.encodeComponent(...)`. Missing keys fail immediately with `UnexpectedClientError(stage: ClientErrorStage.requestBuild)` before hitting the transport.
- `query` accepts a `Map`, `HttpHeadersMap`, or any Tukan model exposing `toJson()`. Entries with `null` values are omitted; `List` entries repeat the key (`?tags=a&tags=b`, skipping `null` items); `DateTime` serializes via `.toIso8601String()`; nested `Map`/`List` values serialize via `jsonEncode`; enums unwrap via `.toJson()`.

### Headers & Cookies Precedence

`HttpHeadersMap` stores keys case-insensitively (lowercased). Headers merge in ascending precedence (later overrides earlier without mutating caller maps):

1. `config.headers`
2. `config.headersProvider(HeadersContext)`
3. `operation.headers` (from `Paths` `.headers(...)`)
4. Per-call `headers:` argument

Cookies (`operation.cookie` and per-call `cookie:`) merge into the `cookie` header as URL-encoded `key=value` pairs joined by `; `, appending to any explicit `cookie` header already present.

### Body Serialization & `Content-Type` Precedence

Effective `Content-Type` precedence: explicit per-request `headers['Content-Type']` > `contentType` parameter (`operation.contentType` or explicit `contentType:`) > inherited `config.headers['Content-Type']` > `'application/json'` default.

| Effective MIME / Input | Serialization Behavior |
|---|---|
| `MultipartBody` or `multipart/form-data` | Encodes RFC 7578 multipart payload (`----TukanBoundary...`) and **always** sets `Content-Type: multipart/form-data; boundary=...`. Handles `MultipartFile`, `List<int>`/`Uint8List` (emitted with `filename="<fieldName>"` and `application/octet-stream`), scalar fields, `DateTime`, repeated arrays, and nested JSON objects/enums. |
| `application/x-www-form-urlencoded` | Sends raw `String` as UTF-8, or serializes a `Map`/Tukan model via `encodeSearchParams`. |
| `application/json` or `application/*+json` | UTF-8 encodes `jsonEncode(body)` (`jsonEncode` automatically calls `.toJson()` on Tukan models/enums). |
| Any other MIME (`text/*`, `application/octet-stream`, etc.) | Accepts `Uint8List`, `List<int>`, or `String` (UTF-8); any other body type yields `UnexpectedClientError(stage: ClientErrorStage.requestBuild)`. |

### Response Body Parsing

- `HEAD` requests, `204`/`205`/`304` responses, `Content-Length: 0`, and empty `bodyBytes` skip parsing and yield `null`.
- JSON MIME types (`application/json`, `application/*+json`) decode UTF-8 and run `jsonDecode` (whitespace-only bodies yield `null`). Malformed JSON becomes `DecodeError` on `2xx` or `UnexpectedHttpError` on non-`2xx`.
- Empty MIME or `text/*` decodes UTF-8 `String` (malformed UTF-8 fails as `DecodeError` / `UnexpectedHttpError`).
- Binary/other MIME types return `Uint8List`.

## 6. Execution Pipeline, Hooks & 401 Token Refresh

Each call passes through these stages inside `TukanClient`:

1. Build URI (`stage: requestBuild`)
2. Call `config.headersProvider` (`stage: hook`)
3. Merge headers/cookies and serialize request body (`stage: requestBuild`)
4. Run `config.onRequest` hooks sequentially (`stage: hook`)
5. Send `RawHttpRequest` via `HttpTransport` composed with `CancelToken` & `timeout` (`inTransport = true`)
6. Run `config.onResponse` hooks sequentially (`stage: hook`; non-null return replaces `response`)
7. Parse response body and decode success (`2xx`) or error (non-`2xx`) payload
8. On any failure, run `config.onError` hooks sequentially (`ApiError<Object?>`), then return `ApiFailure<T, E>`

If any hook (`headersProvider`, `onRequest`, `onResponse`, or `onError`) throws, it never escapes uncaught — it becomes `UnexpectedClientError(stage: ClientErrorStage.hook)`.

### Single-Flight 401 Refresh Example

Use `onResponse` to refresh expired tokens and replay the failed request transparently:

```dart
Future<RawHttpResponse?> refreshOnUnauthorized(
  RequestContext context,
  RawHttpResponse response,
) async {
  if (response.statusCode != 401 || context.extra['_retried'] == true) {
    return null;
  }

  final bool refreshed = await runSingleFlightRefresh();
  if (!refreshed) return null;

  context.extra['_retried'] = true;
  context.headers.set('Authorization', 'Bearer ${tokenStore.accessToken}');

  return transport.send(
    RawHttpRequest(
      method: context.method,
      uri: context.uri,
      headers: context.headers,
      body: context.body,
      followRedirects: context.followRedirects,
      maxRedirects: context.maxRedirects,
      persistentConnection: context.persistentConnection,
      extra: context.extra,
    ),
  );
}
```

See end-to-end tests covering concurrent single-flight refresh, retry-once guards, and bounded retries in `test/client_test.dart`.

## 7. Cancellation & Timeouts

```dart
final token = CancelToken();

// Cancel from another callback (e.g. widget dispose or search debounce):
token.cancel('user left screen');

final result = await client.send(op.request, cancelToken: token);
if (result case ApiFailure(error: CancelledError(:final reason))) {
  // Handled without showing an error dialog.
}
```

`CancelToken` exposes `isCancelled`, `reason`, `Future<Object?> get whenCancelled`, and `addListener(...)` (returning an unsubscribe callback).

- When both `cancelToken` and `timeout` (or `config.timeout`) are active, `TukanClient` creates a linked token so whichever fires first aborts the request.
- `IoHttpTransport` calls `ioRequest.abort(...)` immediately when cancelled, tearing down the active `dart:io` socket instead of waiting for the server to finish.

## 8. Manual Requests, `PathClient`, `ApiEndpoint` & `Decoders`

When calling endpoints without a generated `Paths` tree, `TukanClient` exposes:

- Method helpers: `get<T>`, `post<T>`, `put<T>`, `patch<T>`, `delete<T>`, `head`, `options<T>`, and `request<T>` returning `Future<ApiResult<T, Object?>>` (and `Future<ApiResult<void, Object?>>` for `head`).
- Path-scoped wrapper: `client.path('/users/{id}').get<User>(pathParams: ..., fromJson: User.fromJson)`.
- Declarative `ApiEndpoint<T>`: `const ep = ApiEndpoint<User>(method: HttpMethod.get, path: '/users/{id}', fromJson: User.fromJson); await client.call(ep, pathParams: ...);`.

### Reusable `Decoders`

For manual calls returning top-level collections, primitives, or binary bytes:

- `Decoders.list(Model.fromJson)` -> `List<Model>`
- `Decoders.enumList(MyEnum.fromJson)` -> `List<MyEnum>`
- `Decoders.primitiveList<String>()` -> `List<String>`
- `Decoders.map(Model.fromJson)` -> `Map<String, Model>`
- `Decoders.string`, `Decoders.integer`, `Decoders.number`, `Decoders.boolean`, `Decoders.bytes` (`Uint8List`)

## 9. Custom Transports & Unit Testing

Implement `HttpTransport` to integrate Flutter Web, `package:http`, `dio`, or custom certificate pinning:

```dart
abstract interface class HttpTransport {
  factory HttpTransport.fromHandler(
    FutureOr<RawHttpResponse> Function(RawHttpRequest request) handler, {
    void Function()? onClose,
  });

  Future<RawHttpResponse> send(RawHttpRequest request);
  void close();
}
```

For fast in-memory tests without sockets, use `HttpTransport.fromHandler` together with `RawHttpResponse.json(...)`, `RawHttpResponse.text(...)`, and `RawHttpResponse.empty(...)`:

```dart
final mockTransport = HttpTransport.fromHandler((RawHttpRequest req) {
  if (req.uri.path == '/api/v1/tasks' && req.method == HttpMethod.post) {
    return RawHttpResponse.json(
      <String, Object?>{
        'code': 'validation_error',
        'message': 'Validation failed',
        'fieldErrors': <String, String>{'title': 'Too short'},
      },
      statusCode: 400,
    );
  }
  return RawHttpResponse.empty(statusCode: 204);
});
```
